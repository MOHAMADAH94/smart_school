# المدرسة الذكية — شرح كامل للنظام

منصة **SaaS متعددة المستأجرين (Multi-tenant)** لإدارة المدارس عبر السحابة، بواجهة عربية (RTL)، وأدوار وصلاحيات دقيقة، واشتراكات تتحكم بالميزات المتاحة لكل مدرسة.

---

## 1) ما الذي يقدّمه النظام؟

| المجال | ماذا يفعل |
|--------|-----------|
| الطلاب | إضافة، تعديل، تعيين فصل، ملف متكامل، ربط بالنقل |
| المعلمون | ملفات المعلمين وربطهم بالمواد والفصول |
| أولياء الأمور | سجل الأولياء وربطهم بالطلاب + بوابة متابعة |
| الفصول والمواد | مراحل، شعب، مواد، تكليف تدريس |
| الحضور | تسجيل جماعي لطلاب الفصل |
| الدرجات | فصول دراسية، تقييمات (مذاكرة/نصفي/نهائي)، إدخال جماعي |
| النقل | حافلات، سائقون، مسارات، تعيين طلاب |
| المالية | رسوم، مدفوعات، مصروفات (حسب الاشتراك) |
| الإشعارات | للجميع / معلمين / أولياء / إدارة، مع حالة قراءة لكل مستخدم |
| لوحة التحكم | إحصاءات ورؤى للإدارة |
| الاشتراك | باقات Basic / Professional مع تفعيل الميزات |

## 3) مفهوم Multi-tenant (عزل المدارس)

- كل **مدرسة** مستأجر مستقل: طلابها ومعلموها وبياناتها مفصولة عن غيرها.
- المستخدم قد ينتمي لأكثر من مدرسة عبر **SchoolMembership**.
- الطلبات المحمية ترسل رأس **`X-School-Id`** مع JWT.
- الخادم يتحقق أن العضوية موجودة وصحيحة؛ **لا يُثق بأي `school_id` من الواجهة وحدها**.

```
مستخدم → JWT → اختيار مدرسة (X-School-Id) → صلاحيات الدور + ميزات الاشتراك → البيانات
```

## 4) الأدوار والصلاحيات

| الدور | الاستخدام الرئيسي |
|-------|-------------------|
| **SCHOOL_OWNER** | مالك المدرسة: إدارة كاملة + اشتراك + مالية |
| **SCHOOL_ADMIN** | إدارة تشغيلية (طلاب، معلمون، درجات، نقل…) |
| **ACCOUNTANT** | مالية ولوحة تحكم محدودة |
| **TEACHER** | فصوله ومواده فقط: حضور ودرجات |
| **PARENT** | بوابة الأبناء: درجات، حضور، نقل، رسوم |
| **STUDENT** | صلاحيات عرض محدودة (جاهز للتوسع) |
| **SUPER_ADMIN** | صلاحيات شاملة على المنصة |

### ماذا يرى كل دور تقريباً؟

**الإدارة (Owner / Admin)**  
لوحة التحكم، الطلاب، المعلمون، الأولياء، الفصول، المواد (وربط المعلمين)، الحضور، الدرجات (إنشاء تقييمات وفصول دراسية)، النقل، الإشعارات، الاشتراك (للمالك)، المالية (حسب الدور والباقة).

**المعلم**  
فصلي، طلاب فصوله، مواده المسندة، حضور، إدخال درجات على تقييمات موجودة، إشعارات موجّهة له أو للجميع.  
لا ينشئ تقييماً/فصلاً دراسياً ولا يربط المعلمين بالمواد.

**ولي الأمر**  
أبنائي: تبويبات الدرجات (جدول مواد × تقييمات)، الحضور، النقل، الرسوم.  
إشعارات موجّهة له أو للجميع.

## 5) الوحدات بالتفصيل

### 5.1 الطلاب
- قائمة مع بحث وتصفية حسب الحالة/الفصل.
- إضافة طالب مع إمكانية ربط النقل مباشرة.
- ملف طالب بتبويبات: معلومات، أولياء، حضور، درجات، نقل، مدفوعات، ملاحظات.
- تعيين الفصل من القائمة أو الملف.

### 5.2 المعلمون والمواد
- إدارة المعلمين من حساب الإدارة.
- **ربط معلم ↔ مادة ↔ فصل** من صفحة المواد (للإدارة فقط).
- المعلم يرى «موادي» فقط.

### 5.3 أولياء الأمور
- إضافة ولي أمر وربطه بطالب (صلة: أب/أم/وصي…).
- الربط متاح من صفحة الأولياء أو من ملف الطالب.

### 5.4 الحضور
- اختيار فصل وتاريخ.
- تعليم الكل حاضر ثم تعديل الغياب/التأخر.
- المعلم يرى فصوله المسندة فقط.

### 5.5 الدرجات
- **الفصل الدراسي** و**التقييم** (مذاكرة، واجب، نصفي، نهائي…) — إنشاؤهما للإدارة.
- المعلم/الإدارة: اختيار فصل + مادة + تقييم → شبكة درجات → حفظ جماعي (`/api/grades/bulk/`).
- ولي الأمر: جدول مصفوفة (صف = مادة، أعمدة = التقييمات، + متوسط بمنزلتين عشريتين).

### 5.6 النقل
- حافلات، سائقون، مسارات.
- تعيين طالب لحافلة/مسار من النقل أو من إضافة/ملف الطالب.

### 5.7 المالية
- رسوم طلاب، مدفوعات، مصروفات.
- تظهر للإدارة/المحاسب حسب الصلاحية وميزة الاشتراك (`accounting` / `fees` / `payments`).

### 5.8 الإشعارات
- جرس في الشريط العلوي + صفحة `/notifications`.
- عند الإرسال يحدد المدير **المستهدفين**:
  - الجميع
  - المعلمون فقط
  - أولياء الأمور فقط
  - الإدارة فقط
- حالة «مقروء» لكل مستخدم على حدة.

### 5.9 الاشتراكات والميزات
- باقة **Basic**: الطلاب، المعلمون، الفصول، المواد، الحضور، الدرجات، الأولياء، النقل…
- باقة **Professional**: إضافة المحاسبة، الإشعارات، بوابات أولياء/طلاب…
- انتهاء الاشتراك يقيّد الميزات الاحترافية مع الإبقاء على الأساسيات حسب السياسة المعرّفة في الخادم.

### 5.10 المظهر
- ألوان أزرق / أبيض / أسود.
- وضع **نهاري** و**ليلي** (يُحفظ محلياً).

## 9) نموذج الأمان (ملخص)

1. **JWT** للمصادقة.
2. **عضوية مدرسة** إلزامية عبر `X-School-Id`.
3. **صلاحيات الدور** على مستوى كل إجراء في الـ API.
4. **RequiresFeature** لربط الوظائف بالباقة.
5. **نطاق المعلم**: فصول/مواد/طلاب مسندة فقط (أزواج فصل+مادة).
6. **نطاق ولي الأمر**: أبناؤه المرتبطون فقط.

## 11) سيناريوهات استخدام سريعة

1. **إدارة:** ادخل `demo_admin` → أضف طالباً واربطه بفصل ونقل → اربط معلماً بمادة → أنشئ تقييماً → أرسل إشعاراً للمعلمين فقط.
2. **معلم:** ادخل `demo_teacher` → فصلي / الحضور / الدرجات (فصولك وموادك فقط).
3. **ولي أمر:** ادخل `demo_parent` → أبنائي → تبويب الدرجات (جدول المواد والتقييمات) والحضور والنقل والرسوم.

## 12) ملاحظات للتطوير لاحقاً

- صفحتا **الاشتراك** و**الإعدادات** في الواجهة حالياً **قيد التطوير** (غير قابلتين للاستخدام).
- بوابة الطالب قابلة للتوسع بنفس نمط ولي الأمر.
- للإنتاج: عطّل `DEBUG`، غيّر `SECRET_KEY`، استخدم MySQL، وقيّد `CORS` و`ALLOWED_HOSTS`.
- دليل الاستخدام + تقرير الاختبارات: [`USAGE_AND_TEST_REPORT.md`](USAGE_AND_TEST_REPORT.md).
